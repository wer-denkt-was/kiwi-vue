# Changelog

## 2.0.0

Kiwi-Vue 2 integrates with **Kiwi-Server 1.5**, which changed the HTTP API of the generic entity endpoints (see the
Kiwi-Server migration guide, `docs/98-migration-1.5.md`).

This release contains breaking changes.

### Kiwi-Server 1.5 integration

- `CrudService.update` sends `PATCH /<entity>/{id}` instead of `PUT`; Kiwi-Server 1.5 removed the `PUT` route.
  Updates are partial: Only the properties present in the body are changed.
- `CrudService` and `basicCrudService` take the JSON body types of create and update commands as type parameters:
  `basicCrudService<T, ID, C, U>`, matching the `ICreate…`/`IUpdate…` interfaces generated by Kiwi-Server.
- `ApiError.errors` contains the nested errors of an error, e.g. the field errors of `entity-body-invalid`, which
  Kiwi-Server reports for invalid, missing and unknown body properties of generic commands. Error transformers
  transform them into `ApiErrorDetails.causes`.
- `ApiError` has the HTTP `status` and the `errorType` of the error response.
- New `CrudService.fetchMetadata()` (`GET /<entity>/_schema`) and `AnalyticalReportService.fetchReportSchema()`
  (`GET /<entity>/_report/_schema`), with the types `GenericMetadata` and `AnalyticalReportSchema`.

### Fixes

- Request paths are resolved relative to the API URL: a leading slash, or an API URL without a trailing slash, resolved
  paths against the origin, e.g. report queries always requested `/<entity>/_report` without the API path.
- Error responses without JSON body (e.g. `401` from Spring Security, or errors of a proxy) rejected with a
  `SyntaxError`; they reject with an `ApiError` by status now. Empty success responses (e.g. `204`) resolve to
  `undefined`.
- `403` responses discarded the error body; the error code of the body is used now (see below).
- `LoadingService`: Completing an outdated operation removed the abort controller of the latest operation, and stored
  its result as previous result; `reset()` did not ignore a pending operation; the `pending` state always contained a
  `previousResult` key, even before the first result.
- `loadAllPages` returned only the first page if the requested page size exceeded the server's maximum page size.
- `i18nErrorTransformer`: Keys with multiple conditions (`code[a=1,b=2]`) never matched, and conditions with uppercase
  values (`[entityType=User]`) never matched.
- `JwtBearerToken`: Claims with non-ASCII characters failed to decode, and tokens without `exp` claim were always
  invalid.
- `httpBasic` failed for non-Latin-1 characters; credentials are encoded as UTF-8.
- `addRequestHeader` dropped existing headers given as `Headers` instance or array.
- `ApiError` messages contained `[object Object]` for object details; `errorMessage(undefined)` returned `undefined`.
- `CredentialsInvalid` no longer contains the credentials in its `details`, so passwords and tokens don't end up in
  error messages and logs; they are still available as `credentials` property.
- `Compare.number` and `Compare.caseInsensitive` return an `Ordinal` (`-1`, `0`, `1`) as declared.
- `sorting(compare)` passes `undefined` items to the comparator, `Array.prototype.sort` placed them last without
  comparing them, so `Compare.nullsFirst` sorted `undefined` items last.
- `validateAsInt` accepted strings with trailing characters (`12abc`) and decimals (`1.5`); it requires the integer
  format of `isLikeInt` now.
- Successful responses whose body is not valid JSON (e.g. an HTML page of a development server) rejected with a
  `SyntaxError`; they reject with an `ApiError` with code `response-not-json` now.

### Improvements

- Session cookie authentication, e.g. after an OAuth2/OIDC login performed by the server:
    - `SessionCredentials` send requests with `credentials: 'include'`, add the CSRF token of a `CsrfTokenSource` to
      state-changing requests, and don't follow redirects, so that a redirect to the login page rejects with an
      `UnauthorizedError` (status `0`, detail `redirected: true`).
    - `csrfTokenEndpoint(url)` loads the CSRF token from a server endpoint, `csrfTokenCookie()` reads it from the
      `XSRF-TOKEN` cookie.
    - `createSession`, `provideSession` and `useSession` provide a `SessionService`, tracking the session user, and
      navigating to the login and logout endpoints.
    - `ApiCredentials.prepare(init)` prepares requests asynchronously before `authenticate`, e.g. loading a CSRF token.
    - `extendCredentials(credentials, ...fns)` adds authentication functions (e.g. headers) to credentials.
- `createApi(options)` creates an `Api` outside of components; `provideApi` accepts an `Api` instance as well.
- `ApiOptions.fetch` sets the `fetch` implementation, e.g. for tests or server-side rendering.
- All `CrudService` and `AnalyticalReportService` methods accept a `signal` to abort requests, e.g. combined with the
  `abort` option of `LoadingService.load`.
- `JwtBearerToken` accepts a leeway in seconds, and provides `expiresAt`.
- `computeState` maps the `previousResult` of a pending state as well.
- `LoadingService.emplace(value)` sets a loaded result immediately, aborting and ignoring a pending operation.
- `columnFilter(column, operator, values)` creates column filter parameters (`<column>:<operator>=<values>`) for the
  `filter` of paginated queries, escaping commas and backslashes within values.
- `loadAllPages` accepts several sort orders, its options type is exported as `LoadAllPagesOptions`.
- New exports: `apiErrorTransformer`, `findErrorMessageKey`, `parseErrorMessageKey`, `readResponseError`, `sortParams`,
  `UnauthorizedError`, `errorMessage` (from `utils`).
- Unit and component tests (Vitest, Vue Test Utils), run with `npm test`, or `npm run coverage` for a coverage report.
- Development dependencies upgraded to TypeScript 6 and ESLint 10.

### Migrating from 1.x

1. Upgrade the server to Kiwi-Server 1.5: Kiwi-Vue 2 sends `PATCH` for updates, which Kiwi-Server 1.4 does not accept.
2. **Request paths** are relative to the API URL. If you call `api.request('/path', …)` to request a path outside of
   the API URL, pass an absolute `URL` instead: `api.request(new URL('/path', api.baseUrl), init)`.
3. **CRUD services**: replace the method type parameters of `create<POST, R>` and `update<PUT, R>` by the class type
   parameters, e.g. `basicCrudService<ITodoItemDefault, TodoItemId, ICreateTodoItem, IUpdateTodoItem>('TodoItem')`.
   The result type parameter remains: `create<R>(body)`, `update<R>(id, body)`.
   Send only the properties declared by the command: Kiwi-Server 1.5 rejects unknown properties (e.g. `id`) with
   `entity-body-invalid`, and generic `reference(…)` properties use the schema field name as JSON key (e.g. `list`
   instead of `listId`).
4. **Error messages**:
    - Add messages for `entity-body-invalid` or its nested codes (`entity-field-missing-value`, `entity-field-invalid`,
      `entity-field-unknown`, `entity-mismatched-input`). Without a message for `entity-body-invalid`, the messages of
      its nested errors are shown.
    - `ForbiddenError` uses the error code of the response body if present, e.g. `access-denied` for Spring Security's
      `AccessDeniedException` or the code of a `DomainException`. Add messages for these codes besides `forbidden`.
    - `401` responses reject with `UnauthorizedError` (code `unauthorized`, or the code of the response body).
    - `resourceErrorTransformer`: a condition on an absent detail no longer matches (it matched before).
    - `i18nErrorTransformer`: conditions are separated by `,` as documented (`&` is supported as well).
5. **`Api` implementations**: `request` takes optional `params`/`init`,
   `jsonRequest(path, body, method, params?, init?)` accepts `PATCH` and `DELETE`.
6. **`Ordinal`** is a constant object with a union type instead of a `const enum`, usable with `isolatedModules`.
   `Ordinal.LT`, `Ordinal.EQ` and `Ordinal.GT` work as before.
7. `CredentialsInvalid.details` no longer contains `credentials`, use the `credentials` property.
8. `UsernamePassword.userDetails` (always `null`) was removed.
9. **`FetchApi`** takes the `fetch` implementation as second, and the request preprocessor as optional third
   constructor parameter: `new FetchApi(baseUrl, fetch?, preprocessor?)`. Prefer `createApi(options)`.
